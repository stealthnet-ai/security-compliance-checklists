# FDA Premarket Cybersecurity Penetration Testing Checklist

Prepare a penetration-testing evidence package for a connected medical device and its supporting ecosystem, including device hardware, firmware, companion applications, APIs, cloud services, and third-party integrations.

**[Download the FDA Premarket Penetration Testing Checklist](./FDA-510k-Penetration-Testing-Checklist.pdf)**

## Who should use it

- Medical-device manufacturers preparing 510(k), De Novo, PMA, or related premarket cybersecurity documentation
- Product security, software, quality, and regulatory teams
- Medtech advisers coordinating cybersecurity testing and evidence

## What it covers

- System boundary, trust-boundary, and data-flow definition
- Device hardware, firmware, debug interfaces, and update mechanisms
- Companion mobile or desktop application security
- Backend API, cloud, tenant-isolation, and data-protection testing
- Reporting, remediation, retest, and postmarket planning inputs

## Preparing credible evidence

Use a release-representative build where appropriate. Preserve the approved rules of engagement, test access model, test scope, methodology, findings evidence, risk rationale, remediation status, and retest evidence with the product’s cybersecurity documentation.

FDA cybersecurity guidance provides recommendations for device design and the documentation FDA recommends in premarket submissions. This checklist is a preparation aid and should be aligned to the current FDA guidance, device type, risk profile, and submission strategy.
